# Git & GitHub Workflow Demo

This repository demonstrates a complete Git and GitHub collaboration workflow, built as part of a Day 1 practical assignment covering core version control concepts.

## Objective

Build a repository showcasing:
- Branching strategy with multiple feature branches
- Merge conflict identification and resolution
- Rebase, stash, and cherry-pick operations
- Git tagging
- Pull Request (PR) based collaboration workflow

## What This Repo Demonstrates

### 1. Repository Initialization
- Initialized a Git repository and connected it to GitHub as a remote origin.

### 2. Branching Strategy
- Created multiple feature branches (`feature-a`, `feature-b`, `feature-c`, `feature-d`, `feature-final`) off the `main` branch to simulate parallel development work.

### 3. Merge Conflicts
- Deliberately introduced conflicting changes to the same file across branches to simulate real-world team collaboration scenarios.
- Resolved **2 merge conflicts** directly through GitHub's Pull Request interface.

### 4. Pull Request Workflow
- Opened Pull Requests for each feature branch.
- Reviewed changes, resolved conflicts, and merged PRs into `main` following standard GitHub collaboration practices.

### 5. Additional Git Operations Practiced
- **Rebase**: Replayed feature branch commits on top of the latest `main` for a cleaner, linear history.
- **Stash**: Temporarily saved uncommitted changes while switching branches.
- **Cherry-pick**: Selectively applied a specific commit from one branch to another.
- **Tags**: Created an annotated tag (`v1.0`) to mark a release point in history.
